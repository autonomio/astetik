# Roadmap

This page owns Astetik's intended direction from **2026-10-02 through 2027-10-02**. It guides contribution priorities; the [product boundary](Boundary.md) owns current behavior. Intended work remains subject to scientific need, reviewed changes, and actual verification.

## Intended work

| Researcher need | Direction for the next year | Acceptance boundary |
| --- | --- | --- |
| Give an agent the same reliable instructions as a human | Keep catalogue selection, explicit specifications, immutable manifests, and structured failures consistent across Python and CLI | Verify the documented workflow and retained result identities on real supplied inputs |
| Put every supported representation into a paper | Refine final-size typography, axes, legends, layout, and semantic color through the central manifest | Inspect actual exported figures and enforce existing paper contracts across the catalogue |
| Explain and repeat what was computed | Strengthen source, observation, preparation, method, font, environment, and artifact provenance without hidden transformations | Retain inspectable evidence and exercise strict replay and explicit changed-environment comparison |
| Adopt maintained software with verifiable origin | Complete signed software distribution, transparent vulnerability response, dependency maintenance, and truthful OpenSSF evidence | Verify actual published artifacts and public evidence; configuration or a questionnaire alone is insufficient |
| Maintain the package without relearning its conventions | Keep canonical task documentation, migration guidance, automated checks, and backup access current | Test installed-package examples and update the affected contract with every behavior change |

Prioritize defects and requests demonstrated by researchers' own data and publication requirements. Add scientific methods only with explicit assumptions, numerical reference checks, and provenance that a researcher can inspect.

## Work excluded during this period

Astetik will not become a data-acquisition, preparation, experiment-training, or general statistical-modeling platform. Preparation and unit conversion remain explicit upstream responsibilities. The package will not infer causal validity, choose undisclosed scientific assumptions, silently remove observations, or invent empirical data.

Keep agent and human workflows on the same compiler rather than introduce a separate decision engine or notebook-global style state. General localization of project-authored messages and a hosted research/account service are outside this year's planned scope; user-supplied Unicode figure labels remain supported.

The roadmap does not promise release dates, universal security, journal acceptance, or identical rendering across unrecorded environments. It does require actual evidence before those bounded product claims are made.

## Maintenance

Maintainers review priorities when accepting material product changes or releases and record decisions in issues and reviewed documentation. Update this page when direction changes and retain at least the next year's intended and excluded work. [Governance](../../GOVERNANCE.md) defines who decides; [contributing](../../CONTRIBUTING.md) defines the change process.
